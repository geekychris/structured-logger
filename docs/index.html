Headline numbers

Measured on identical workload: 2000 records/sec, 180 s, ~390-byte JSON records.

Approach p50 latency Wire bytes / 300k $ / M rows
A — Kafka + JSON+Snappy 6.95 ms 120 MiB JSON $0.112
B — Kafka + Avro + SR 7.09 ms 63 MiB Avro $0.113
E — WarpStream (Kafka API) 397.92 ms 128 MiB JSON $0.078
C — Sidecar → S3 Avro 11.85 s 51 MiB $0.0083
D — Sidecar → S3 Parquet+Zstd 13.83 s 35 MiB $0.0074

Three regimes ~50× apart in latency. Sidecar approaches are 15× cheaper at this throughput — but Kafka's broker cost amortises and beats sidecars above ~100M rows/hr.

What's in the project

📊 Benchmark

Self-contained docker-compose harness in bench/ comparing all 5 approaches on latency, CPU, network, storage, and per-million-row cost extrapolated to AWS list prices. Includes a per-column Parquet compression deep-dive showing why categorical columns compress 1000× while free-text dominates the at-rest cost.

🔌 Production sinks

All five transports wired into the production loggers (Java + Python), driven by one config field. Switch between Kafka+JSON, Kafka+Avro+SR, Sidecar→S3+Avro, Sidecar→S3+Parquet+Zstd, or WarpStream by editing transport.sinks in your log-configs/*.json.

→ Approach availability matrix

🌊 End-to-end

Two Spark consumers (kafka-to-iceberg + s3-to-iceberg) land all five paths into the same Iceberg tables. Trino queries them identically — the transport choice is completely hidden from downstream analytics.

📋 Reproducible

Three commands bring up a coordinated lakehouse stack (Kafka, MinIO, Hive Metastore, Spark, Trino, Schema Registry) on a devportal-allocated port range that won't collide with other dev stacks running on the same machine.

Try it locally

# 1. Clone the lakehouse stack alongside this project
git clone https://github.com/geekychris/spark_minio_trino.git ../spark_minio_trino

# 2. Bring it all up (devportal-coordinated ports 18000–18099)
docker compose -f ../spark_minio_trino/docker-compose.yml \
               -f lakehouse-override.yml up -d

# 3. Start the consumers and drive sample data through every approach
./start-consumer.sh both
python3 test_e2e.py

# 4. Query the results from Trino — same query for every transport
docker exec trino trino --server localhost:8080 --execute "
  SELECT 'A: kafka+json'         AS approach, COUNT(*) FROM iceberg.analytics_logs.user_events
  UNION ALL SELECT 'B: kafka+avro+SR',         COUNT(*) FROM iceberg.analytics_logs.user_events_kafka_avro
  UNION ALL SELECT 'C: sidecar→s3 avro',       COUNT(*) FROM iceberg.analytics_logs.user_events_s3_avro
  UNION ALL SELECT 'D: sidecar→s3 parquet',    COUNT(*) FROM iceberg.analytics_logs.user_events_s3_parquet
"
